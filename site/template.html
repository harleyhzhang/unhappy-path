Table stakes

Tasks

Six one-page product briefs with a small JSON API. The brief says nothing about loading, errors or screen sizes.

Method

One agent harness, one starting project and a 20-minute limit for every model. The write-up has the detail.

Brief

A product page and its API, with sample data to develop against.

Build

The agent works in a sandbox that cannot read the grader, the grading data or any other run.

Gate

The normal flow is scripted against different data. An app that fails scores zero.

Stress

The app is rebuilt from source and replayed once per condition, with faults injected from outside.

Verdict

Each stress passes or fails by a written rule on browser measurements.

Limits

What the numbers do and do not cover.

  • No independent human checkThe verdicts have had one blind second read by an AI agent on the author's side, 31 of 32 in agreement. A check by people who did not write the rules is still owed.
  • Repaired in flightAn earlier round was withdrawn after a builder read the grading code. This run also had retried attempts, one replaced artifact and a note added to the starting project partway through.
  • Fable was added laterGenerated two days after the other six through a different access path, then rerun from the same starting project as the original runs. The rerun is reported; it scored within one point of the first run.
  • One harness, uneven settingsAccess paths and reasoning settings differ between models. A difference between rows is a difference between model-and-configuration pairs.
  • Small and narrowTwelve tasks across two rounds, all single-page React apps from families the rules were developed on. Intervals are wide and neighbouring models overlap.
  • ProxiesFocus visibility is a style change, zoom is a smaller viewport, announcements are read from the accessibility tree. Passing the layout checks does not make a page usable.
